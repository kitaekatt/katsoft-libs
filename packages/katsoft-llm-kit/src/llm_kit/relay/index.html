• llm_kit The llm_kit core library: the unified completion protocol across OpenAI-compatible HTTP, Claude CLI, Codex CLI, and OpenCode CLI backends, with dispatch routing, the front-door API, the graph viewer, the CLI, job and run management, and the deployment-mode runtime

The relay, hub, and channel clients that carry session messages, LLM completions, and operator questions between coding-agent sessions across a fleet of machines.

This is the relay subsystem: the per-machine message broker, the MCP hub that fronts it for remote clients, and the channel clients an owner launches in a terminal. A frozen wire contract ( relay-protocol/1) defines every envelope, error code, verb, and state transition; each unit builds against it and the JSON Schemas stored beside it. The relay and hub bind loopback only; a tunnel in front of the hub is the only external entry. Under the relay's security posture, file modes and credential checks are guardrails against accidental calls, not boundaries against a same-user process.

Where to start

Open packages/katsoft-llm-kit/src/llm_kit/relay/protocol.py first: it freezes the envelopes, the stable error codes, the address grammar, every verb as a request/response pair, and the mailbox state machine. The JSON Schemas in the schemas directory validate every request and response against it.

Routes

  • Read the wire contract
    1. packages/katsoft-llm-kit/src/llm_kit/relay/protocol.py defines the contract
    2. the 55 JSON Schemas beside it pin every request and response shape
    3. packages/katsoft-llm-kit/src/llm_kit/relay/client.py implements every verb as one method
  • Hub reaches a relay
    1. packages/katsoft-llm-kit/src/llm_kit/relay/hub.py builds one relay client per machine
    2. packages/katsoft-llm-kit/src/llm_kit/relay/client.py posts each verb as a JSON envelope
    3. packages/katsoft-llm-kit/src/llm_kit/relay/protocol.py defines the envelope and the check order
  • Start a Codex channel
    1. packages/katsoft-llm-kit/src/llm_kit/relay/config.py: the relay config must hold enabled: true
    2. packages/katsoft-llm-kit/src/llm_kit/relay/codex_channel.py registers with the relay and polls for messages
    3. packages/katsoft-llm-kit/src/llm_kit/relay/codex_appserver.py owns the app-server child over stdio

Wire contract

  • packages/katsoft-llm-kit/src/llm_kit/relay/protocol.py: the frozen wire contract. Envelopes, error codes, address grammar, every verb, mailbox states and transitions. Read before any implementation unit.
  • packages/katsoft-llm-kit/src/llm_kit/relay/schemas: 55 JSON files and 5 helper modules. The request and response schemas that validate every verb. No individual schema is a starting point; the protocol module is.
  • packages/katsoft-llm-kit/src/llm_kit/relay/__init__.py: module docstring only. No re-exports; import from the owning module.

Configuration and state

  • packages/katsoft-llm-kit/src/llm_kit/relay/config.py: machine identity, bind addresses, state paths, peer credentials, and the loopback model registry. Pure, creates nothing. Open when tuning ports, adding a peer, or changing the model endpoints.
  • packages/katsoft-llm-kit/src/llm_kit/relay/lifecycle.py: state directory, singleton role lock, token persistence, pause flags, and the registry file. Everything under the state directory is created and validated here.

Relay services

  • packages/katsoft-llm-kit/src/llm_kit/relay/mailbox.py: the SQLite ledger. Message state machine, one-use grants, append-only audit, and named conversations. One file per machine.
  • packages/katsoft-llm-kit/src/llm_kit/relay/discovery.py: session discovery. Merges channel registrations with harness-store scans (Claude session files, Codex rollouts and writer locks). Serves list_sessions and read_session.
  • packages/katsoft-llm-kit/src/llm_kit/relay/llm.py: the ask_llm service. Resolves a loopback endpoint, checks consent explicitly, calls the backend, and stores turns in the mailbox.
  • packages/katsoft-llm-kit/src/llm_kit/relay/questions.py: operator questions. Lists and answers job interrupts from watched ledgers; the answer path mirrors llm-kit jobs resolve.
  • packages/katsoft-llm-kit/src/llm_kit/relay/redact.py: redaction for read_session. Replaces secret shapes in text and withholds tool calls that touch secrets paths.
  • packages/katsoft-llm-kit/src/llm_kit/relay/resume.py: remote resume (amendment 3). The one place the relay starts a process: it runs one turn in an idle session for continue_session.

Hub

  • packages/katsoft-llm-kit/src/llm_kit/relay/hub.py: the hub. An MCP server over streamable HTTP in front of one or more relays. Serves nine tools; binds loopback only; a tunnel serves the public URL.
  • packages/katsoft-llm-kit/src/llm_kit/relay/hub_oauth.py: single-user OAuth 2.1 sign-in for the hub. On only when a public URL is configured; the consent page prints a one-time code to the hub's terminal.

Clients and channels

  • packages/katsoft-llm-kit/src/llm_kit/relay/client.py: the HTTP client. One connection to one relay, one method per verb. Handles loopback and peer URLs, the sent flag on transport errors, and forwarding with a peer key.
  • packages/katsoft-llm-kit/src/llm_kit/relay/codex_appserver.py: stdio client for codex app-server. JSON-RPC over pipes; approval always refused; POSIX only. Open when debugging a thread or a turn that will not complete.
  • packages/katsoft-llm-kit/src/llm_kit/relay/codex_channel.py: the Codex channel. Runs in the owner's terminal, registers with the relay, polls for messages, and runs one turn per message. Off unless the relay config opts in.
