• llm_kit The llm_kit core library: the completion protocol and its four provider backends (OpenAI-compatible HTTP, Claude CLI, Codex CLI, OpenCode CLI), dispatch routing, the front-door API, the graph viewer, the CLI, and the deployment-mode runtime.

The relay, hub, and channel clients that carry session messages, LLM completions, and operator questions between coding-agent sessions across a fleet of machines.

This is the relay subsystem of llm-kit: a per-machine broker, a fleet-wide MCP hub, and the channel clients that bind coding-agent sessions to each other. One frozen wire module and its fifty-five JSON schemas define the contract; the relay server, the hub, and two channel implementations build against it. Everything binds loopback only. Configuration is opt-in per machine via a single YAML file, and all state lives under a private XDG directory.

Where to start

Open packages/katsoft-llm-kit/src/llm_kit/relay/protocol.py first for the envelope grammar, verb table, error codes, and address format. The schemas subdirectory beside it pins each verb's request and response shape as a JSON Schema.

Routes

  • Boot a relay on this machine
    1. packages/katsoft-llm-kit/src/llm_kit/relay/config.py reads relay.yaml, resolves the machine label from env.json, and checks the opt-in gate
    2. packages/katsoft-llm-kit/src/llm_kit/relay/lifecycle.py creates the state directory, tokens, and the singleton role lock
    3. the relay server binds loopback and serves the protocol verbs
  • Hub reaches a peer relay
    1. packages/katsoft-llm-kit/src/llm_kit/relay/hub.py validates the tool call against the verb schema and checks pause
    2. packages/katsoft-llm-kit/src/llm_kit/relay/client.py sends the POST with the peer key header to the peer HTTPS URL
    3. the peer relay answers with its result envelope
  • One Codex channel turn
    1. packages/katsoft-llm-kit/src/llm_kit/relay/codex_channel.py polls the relay and receives a message
    2. packages/katsoft-llm-kit/src/llm_kit/relay/codex_appserver.py starts a turn on the app-server child with the turn header
    3. the channel acks on acceptance, waits for completion, and replies to the relay

Wire contract

  • packages/katsoft-llm-kit/src/llm_kit/relay/protocol.py: the frozen relay-protocol/1 module: envelopes, verb table, stable error codes, address grammar, and the mailbox state machine
  • packages/katsoft-llm-kit/src/llm_kit/relay/schemas: fifty-five JSON Schemas defining each verb's request and response shape, plus grant and audit structures

Configuration and process state

  • packages/katsoft-llm-kit/src/llm_kit/relay/config.py: machine identity, bind addresses, peer list, loopback model registry, and the relay.yaml opt-in gate
  • packages/katsoft-llm-kit/src/llm_kit/relay/lifecycle.py: state directory, token files, singleton role lock, pause flags, and peer credential management
  • A Windows ACL helper, a transcript reader, and the relay server process itself round out the support modules

Transport and routing

  • packages/katsoft-llm-kit/src/llm_kit/relay/client.py: the HTTP client that sends one POST per verb, with loopback and peer URL rules and a sent-or-not error model
  • A routing module verifies that machine labels in hub results are allowed by the target relay

Hub and sign-in

  • packages/katsoft-llm-kit/src/llm_kit/relay/hub.py: the MCP server serving nine tools over one or more relays, with fan-out, pause, and schema validation
  • packages/katsoft-llm-kit/src/llm_kit/relay/hub_oauth.py: single-user OAuth 2.1 sign-in for the claude.ai connector, active only when the hub publishes a public URL

Channel clients

  • packages/katsoft-llm-kit/src/llm_kit/relay/codex_channel.py: the owner-launched Codex channel: register, poll, one turn per message, reply
  • packages/katsoft-llm-kit/src/llm_kit/relay/codex_appserver.py: the stdio JSON-RPC client for a codex app-server child, with sandbox and approval safety rules

Session and message services

  • packages/katsoft-llm-kit/src/llm_kit/relay/discovery.py: merges channel registrations with harness-store scans to answer list_sessions and read_session
  • packages/katsoft-llm-kit/src/llm_kit/relay/mailbox.py: the SQLite ledger for messages, grants, audit rows, and named conversations
  • packages/katsoft-llm-kit/src/llm_kit/relay/llm.py: the ask_llm service with loopback endpoint resolution and explicit consent checks
  • packages/katsoft-llm-kit/src/llm_kit/relay/questions.py: list_questions and answer_question over watched job ledgers
  • packages/katsoft-llm-kit/src/llm_kit/relay/resume.py: the remote-resume runner that starts one turn in an idle session for continue_session

Redaction

packages/katsoft-llm-kit/src/llm_kit/relay/redact.py replaces secret shapes in text and detects tool calls that touch credential paths, so a remote reader of a transcript never receives a key by accident.
