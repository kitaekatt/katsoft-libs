LLM completion and execution library: shared completion protocol, four provider transports (OpenAI-compatible HTTP, Claude CLI, Codex CLI, OpenCode CLI), endpoint and model registry, dispatch routing, front-door API, graph viewer, CLI, and deployment-mode runtime

This is the LLM completion and execution library. It defines a shared completion contract that four provider transports implement, and the routing, model-registry, and API layers that sit above them. The contract is the organizing seam: every transport speaks the same shape, and a routing layer picks the transport by configuration rather than by code path. The transports wrap HTTP calls or local CLI subprocesses; the layers above compose completions into higher-level operations and expose them through a command-line interface.

Where to start

Open packages/katsoft-llm-kit/src/llm_kit/completion first: it defines the shared types, halt taxonomy, and capability records that every transport implements, so the rest of the library reads as variations on one contract.

Routes

  • Send a completion
    1. The caller names an endpoint and model to the front-door or dispatch layer.
    2. The registry resolves the endpoint to a base URL and credential variable, and the model to a concrete slug.
    3. Dispatch selects a backend factory by the endpoint's transport kind.
    4. The chosen backend builds its request (an HTTP body or a CLI argv) and executes it.
    5. The response is normalized into the shared LLMResponse with cost, usage, and dropped params.
  • Identify the deployment
    1. packages/katsoft-llm-kit/src/llm_kit/_runtime.py reads the packages/katsoft-llm-kit/src/llm_kit/_deployment.py marker for its MODE value.
    2. It verifies the layout is a source file on disk and checks installed distributions for conflicts.
    3. It returns the contract-routing policy; fleet() separately tests whether bootstrap_lib imports in this environment.

Completion protocol

  • packages/katsoft-llm-kit/src/llm_kit/completion -- the shared contract: types, halt taxonomy, capability records, output-contract validation, and skill-context composition. Every transport depends on this; open it when a field on LLMResponse or a dropped param is confusing.

Provider transports

  • packages/katsoft-llm-kit/src/llm_kit/adapters/backends.py -- the OpenAI-compatible HTTP and Claude CLI backends; the seam that lets one pipeline swap transports by config.
  • packages/katsoft-llm-kit/src/llm_kit/adapters/codex_backend.py -- the codex exec transport: result in a file, usage in JSON events, no separate system-prompt channel.
  • packages/katsoft-llm-kit/src/llm_kit/adapters/opencode_backend.py -- the OpenCode run transport: answer on stdout, workspace-guarded posture, no result-file flag.
  • packages/katsoft-llm-kit/src/llm_kit/adapters/claude_runner.py -- the shared prompt-on-stdin subprocess runner with UTF-8 pipes, bounded timeout, and hard-stop kill on rate-limit or auth markers.
  • packages/katsoft-llm-kit/src/llm_kit/adapters/capabilities.py -- the filled capability record per adapter family; the SSOT for what each transport emits, paired with seam tests.

Routing and registry

  • packages/katsoft-llm-kit/src/llm_kit/dispatch -- pacing policy, backend factories, and reachability probes; the layer that turns a named endpoint into a running backend.
  • packages/katsoft-llm-kit/src/llm_kit/registry -- endpoint and model resolution, API-key lookup, cost accounting, and the effort-style planner. Open it when a model alias or a base URL does not resolve as expected.

Front-door and CLI

  • packages/katsoft-llm-kit/src/llm_kit/frontdoor -- the public-facing API that composes completions and exposes backend health; the entry point for consumers that do not drive dispatch directly.
  • packages/katsoft-llm-kit/src/llm_kit/cli -- the command-line interface: account management, endpoint probing, and one-shot completion from the terminal.

Graph viewer

  • packages/katsoft-llm-kit/src/llm_kit/graph -- the graph subsystem: commands, ops, and a viewer that ships a small static asset bundle (one stylesheet, one HTML shell, and six JavaScript modules) for rendering execution graphs in a browser.

Execution, runs, and jobs

  • packages/katsoft-llm-kit/src/llm_kit/execution -- execution support shared by the pipeline and the front-door.
  • packages/katsoft-llm-kit/src/llm_kit/runs -- run records and the state a completed run persists.
  • packages/katsoft-llm-kit/src/llm_kit/jobs -- job definitions and their schemas; the shape a work item takes before dispatch.

Schema, storage, and scaffold

  • packages/katsoft-llm-kit/src/llm_kit/schema -- schema definitions and format helpers for run records, spend data, and prompt files.
  • packages/katsoft-llm-kit/src/llm_kit/storage -- persistence layer beneath the schema.
  • packages/katsoft-llm-kit/src/llm_kit/scaffold -- project scaffolding for new consumers of the library.

Deployment and bootstrap

  • packages/katsoft-llm-kit/src/llm_kit/_runtime.py -- deployment-mode identification: reads the marker, verifies layout and installed metadata, and routes the three shared contracts. Open it when a RuntimeIdentityError or ContractsMissing surfaces.
  • packages/katsoft-llm-kit/src/llm_kit/_deployment.py -- the one-line provenance marker; the build hook rewrites it for release wheels.
  • packages/katsoft-llm-kit/src/llm_kit/bootstrap_guard.py -- stdlib-only bootstrap-presence detection and venv re-exec; vendored byte-for-byte into every plugin that needs it.
