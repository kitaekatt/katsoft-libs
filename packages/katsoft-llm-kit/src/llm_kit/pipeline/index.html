Stage orchestration and durable execution for LLM-in-the-loop batch pipelines: single-pass and convergence-loop shapes, the SQLite-backed run store with its prepare/finalize lifecycle and versioned worker protocol, and post-hoc analysis through audit, provenance, and corpus mining.

This is the pipeline subsystem of llm_kit: the layer that drives batch work through LLM calls, tracks every unit of work durably across process boundaries, and mines completed runs for audit and pattern analysis. Two orchestration shapes sit above a shared durable store -- a single-pass stage fold for one-shot work, and a convergence loop that iterates grade, select, apply, fill until a stopping verdict. Below them the execution layer is a SQLite-backed run store with atomic claims, fencing tokens, and a versioned JSON worker protocol a consumer mounts onto its own entry point. The whole thing is built in phases: the store and prepare/finalize controller first, then the worker protocol and adapter contract, with background-session and workflow drivers still ahead.

The pipeline layer

This is the pipeline subsystem of llm_kit: the layer that drives batch work through LLM calls, tracks every unit of work durably across process boundaries, and mines completed runs for audit and pattern analysis. The artifacts layer -- the canonical attributed store, two-tier freshness, in-place and projection delivery, and the version-control seam -- has its own page one level down. Everything on this page is the orchestration and durability that sits above it.

Where to start

Open packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/__init__.py for the full submodule map and the phase-by-phase dependency story; its docstring names every module and what it imports, which is the fastest way to orient yourself against what is still planned.

Routes

  • Convergence loop
    1. packages/katsoft-llm-kit/src/llm_kit/pipeline/core/convergence_loop.py run drives up to max_cycles cycles, each executing the four fixed-order stages grade, select, apply, fill.
    2. packages/katsoft-llm-kit/src/llm_kit/pipeline/core/convergence_loop.py after each cycle the measure reports progress and feeds the gate; packages/katsoft-llm-kit/src/llm_kit/pipeline/core/convergence.py ProgressEvaluator maps the round history to a verdict.
    3. CONVERGED, STALLED, or FAILED stops the run; CONTINUE schedules the next cycle.
  • Tracked run lifecycle
    1. packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/controller.py prepare_run runs gates and freshness over pending units, records terminal skips, and returns the claimable wave.
    2. packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/store.py the driver claims units, submits results, and records attempts through the durable store.
    3. packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/controller.py finalize_run re-parses each accepted unit's recorded text and applies the payload; apply is convergent, so an interrupted apply is simply retried.

Pipeline shapes

  • packages/katsoft-llm-kit/src/llm_kit/pipeline/core/single_pass.py -- single-pass entry: run (stage fold), seed_for (per-unit RNG), and Gate re-exports
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/core/convergence_loop.py -- the grade-select-apply-fill cycle; run drives it to a verdict via the gate
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/core/convergence.py -- ProgressEvaluator: maps round history to CONVERGED, STALLED, CONTINUE, or FAILED
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/core/gate.py -- Gate dataclass and run_gates; the pre-generation gate shape consumed by prepare_run
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/core/workunit.py -- FlatChunk and GraphWalk strategies; the units() interface both shapes iterate over
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/core/cell_policy.py -- consumer-owned cell classification; tally and measure_from feed the convergence loop
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/core/seed.py -- deterministic per-unit RNG seed from sha256 of a stable identifier
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/core/vcs_seam.py -- the VcsBackend protocol; deliver drives changesets without knowing which backend is configured
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/core/validate -- validation contracts for output schemas (3 files); imported by the adapter and protocol layers

Durable execution

  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/model.py -- record dataclasses, UnitState machine, AttemptKind, and the error taxonomy
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/controller.py -- prepare_run / finalize_run / pause / resume / record_halt; the prepare/finalize lifecycle
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/adapter.py -- RunAdapter: the consumer's four-responsibility worker contract plus environment checks
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/protocol.py -- versioned JSON worker protocol as mountable handlers; ships no runnable tool of its own
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/scheduler.py -- in-memory DAG scheduler with capacity, deferred priority, and a thread-pool runner
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/parallel_graph.py -- ParallelGraphStrategy: explicit per-unit dependencies run up to a capacity at once
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/deadlines.py -- per-unit wall-time budget, run-wide deadline circuit, and an atomically-written notes file
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/failure_cache.py -- negative cache of deterministic failures keyed by the consumer's attempt key
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/interrupts.py -- the durable wait: typed interrupt requests, resolutions, and the replay test
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/status.py -- bounded RunStatus digest: counts, ages, throughput, capped failure groups; never carries payloads
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/events.py -- read-side projection of the attempt log into shared execution-event envelopes
  • packages/katsoft-llm-kit/src/llm_kit/pipeline/execution/drivers -- the inline concurrency-one driver (A-min.2); background-session and workflow drivers are later phases
