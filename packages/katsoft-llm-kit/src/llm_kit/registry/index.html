The llm-kit endpoint and model registry: defines machine-known LLM endpoints, reads project model files, resolves API keys and request settings, and checks connection consent.

This is the registry layer of llm-kit: the set of modules that declares what endpoints and models a machine can call, resolves their credentials, classifies their cost, and builds the catalogue a project model file drives. No HTTP originates here; every module is a pure reader or validator that the transport and harness adapters consume above it. The layout follows the data flow a selection takes: a project names a model, the registry resolves the endpoint and its effort menu, the credential layer finds the key, and the cost and consent layers decide whether the call is permitted.

Where to start

packages/katsoft-llm-kit/src/llm_kit/registry/models.py shows how a model name resolves through the layered config into a concrete endpoint; every other module here feeds into that resolution. Working from a project model file instead, packages/katsoft-llm-kit/src/llm_kit/registry/catalog.py shows what a validated file produces as a query document.

Routes

  • Resolve a model call
    1. packages/katsoft-llm-kit/src/llm_kit/registry/models.py (layered config)
    2. packages/katsoft-llm-kit/src/llm_kit/registry/model_endpoints.py (YAML registry lookup)
    3. packages/katsoft-llm-kit/src/llm_kit/registry/api_key.py (six-layer credential)
    4. packages/katsoft-llm-kit/src/llm_kit/registry/cost.py (cost class)
  • Read a project catalogue
    1. packages/katsoft-llm-kit/src/llm_kit/registry/project_models.py (parse and validate the YAML)
    2. packages/katsoft-llm-kit/src/llm_kit/registry/catalog.py (build the query document)
    3. packages/katsoft-llm-kit/src/llm_kit/registry/model_profiles.py (exact-model effort menus)
  • Approve a new connection
    1. packages/katsoft-llm-kit/src/llm_kit/registry/project_models.py (endpoint_connection check)
    2. packages/katsoft-llm-kit/src/llm_kit/registry/consent.py (owner approval by host and key variable)
    3. packages/katsoft-llm-kit/src/llm_kit/registry/cost.py (classify the cost class)

Endpoint and model resolution

  • packages/katsoft-llm-kit/src/llm_kit/registry/models.py -- layered config: shipped baseline deep-merged with fleet, user, and project YAML; the named-endpoint map.
  • packages/katsoft-llm-kit/src/llm_kit/registry/model_endpoints.py -- the YAML registry reader: OpenAI-compatible transport entries and harness entries from the user profile file.
  • packages/katsoft-llm-kit/src/llm_kit/registry/adapter_names.py -- the four adapter family names and the retired openrouter-to-openai-compat mapping.
  • packages/katsoft-llm-kit/src/llm_kit/registry/constants.py -- default-endpoint values and the canonical credential file paths.
  • packages/katsoft-llm-kit/src/llm_kit/registry/declaration_syntax.py -- the validator probe for the bootstrap model-declaration contract.
  • packages/katsoft-llm-kit/src/llm_kit/registry/model_overrides.py -- per-user usage policy: disabled and reset-mode switches per entry.

Project catalogue and request

  • packages/katsoft-llm-kit/src/llm_kit/registry/project_models.py -- the tracked catalogue YAML: rows, selections, endpoint connections, request profiles, and the personal layer.
  • packages/katsoft-llm-kit/src/llm_kit/registry/request_settings.py -- layers row, selection, and call settings into a resolved, provider-neutral request.
  • packages/katsoft-llm-kit/src/llm_kit/registry/catalog.py -- builds the catalogue query document behind the models catalog command.

Effort and pacing

  • packages/katsoft-llm-kit/src/llm_kit/registry/effort.py -- effort wire styles, extraction and placement logic, and per-harness effort orders.
  • packages/katsoft-llm-kit/src/llm_kit/registry/model_profiles.py -- measured exact-model effort menus, shipped as data with provenance.
  • packages/katsoft-llm-kit/src/llm_kit/registry/conserve.py -- pacing statuses, the Budget verdict dataclass, and the conserve_usage declaration parser.

Credentials and consent

  • packages/katsoft-llm-kit/src/llm_kit/registry/api_key.py -- six-layer API key resolution with source tracking and a legacy-location notice.
  • packages/katsoft-llm-kit/src/llm_kit/registry/consent.py -- cost-class policy (local, subscription, metered) and connection approvals the owner grants.
  • packages/katsoft-llm-kit/src/llm_kit/registry/cost.py -- pure cost-class classification: fails closed to metered when billing is unverified.
  • packages/katsoft-llm-kit/src/llm_kit/registry/env_file.py -- the KEY=VALUE .env reader and writer with restricted file permissions.
  • packages/katsoft-llm-kit/src/llm_kit/registry/user_paths.py -- the neutral user-file directory and every override environment variable.

Cross-language format readers

  • packages/katsoft-llm-kit/src/llm_kit/registry/fallback_chains.py -- fallback chain format: host ordering and per-host input mapping, shared with the TypeScript package.
  • packages/katsoft-llm-kit/src/llm_kit/registry/reply_cache.py -- reply cache format: request-key computation and stored-entry validation, shared with the TypeScript package.
