• llm_kit The llm_kit core library: the completion protocol and its four provider backends (OpenAI-compatible HTTP, Claude CLI, Codex CLI, OpenCode CLI), dispatch routing, the front-door API, the graph viewer, the CLI, and the deployment-mode runtime.

The llm-kit endpoint and model registry: defines machine-known LLM endpoints, reads project model files, resolves API keys and request settings, and checks connection consent.

This is the registry layer of llm-kit. It answers what this machine can call, with what credential, and how a request goes on the wire. It holds endpoint declarations, model-to-provider resolution, layered credential lookup, the consent and cost-class policy, and the wire vocabulary for reasoning effort. It sits below adapters and dispatch: no HTTP, no network calls. The package has no root re-exports; import from the owning module directly.

Where to start

Start with packages/katsoft-llm-kit/src/llm_kit/registry/catalog.py: it builds the catalogue document and imports every other module here, so it shows how the pieces connect. For the model-name-to-slug resolution underneath, open packages/katsoft-llm-kit/src/llm_kit/registry/models.py

Routes

  • Resolve a model name to a provider call
    1. Read the layered config and resolve the name to an endpoint entry ( packages/katsoft-llm-kit/src/llm_kit/registry/models.py)
    2. Look up the entry in the user-declared registry ( packages/katsoft-llm-kit/src/llm_kit/registry/model_endpoints.py)
    3. Resolve the API key through the six layered sources ( packages/katsoft-llm-kit/src/llm_kit/registry/api_key.py)
    4. Pick the effort style and wire placement for the request ( packages/katsoft-llm-kit/src/llm_kit/registry/effort.py)
  • Build and read a project catalogue
    1. Validate and read the project model YAML ( packages/katsoft-llm-kit/src/llm_kit/registry/project_models.py)
    2. Build the catalogue document with effort menus and cost classification ( packages/katsoft-llm-kit/src/llm_kit/registry/catalog.py)
    3. Resolve a selection's typed request settings across three layers ( packages/katsoft-llm-kit/src/llm_kit/registry/request_settings.py)

Endpoint and model resolution

  • packages/katsoft-llm-kit/src/llm_kit/registry/models.py -- the layered config that resolves a model name to a provider slug; trace how a declaration like defaultCheap becomes a concrete endpoint
  • packages/katsoft-llm-kit/src/llm_kit/registry/model_endpoints.py -- reads the user-declared endpoint registry (YAML); machine-specific host and port facts live in the user's file, not here
  • packages/katsoft-llm-kit/src/llm_kit/registry/model_profiles.py -- measured exact-model effort menus shipped as data; open to see which models accept which levels and from which source
  • packages/katsoft-llm-kit/src/llm_kit/registry/catalog.py -- builds the llm-kit.model-catalog/v1 document from a validated project file; the output of llm-kit models catalog

Project model file and requests

  • packages/katsoft-llm-kit/src/llm_kit/registry/project_models.py -- the per-project catalogue format: validation, canonical rendering, atomic read/write, and the personal local layer
  • packages/katsoft-llm-kit/src/llm_kit/registry/request_settings.py -- resolves a selection's typed request settings across three layers (row, selection, call)
  • packages/katsoft-llm-kit/src/llm_kit/registry/fallback_chains.py -- reads and checks fallback chain files: hosts in order, failure classes, and input mapping rules

Credentials and consent

  • packages/katsoft-llm-kit/src/llm_kit/registry/api_key.py -- resolves an endpoint's API key through six layered sources, from env var down to a bare-value key file
  • packages/katsoft-llm-kit/src/llm_kit/registry/consent.py -- the user-level consent file: an optional cost-class policy and always-on connection approvals
  • packages/katsoft-llm-kit/src/llm_kit/registry/cost.py -- classifies an endpoint as local, subscription, or metered; pure, no I/O
  • packages/katsoft-llm-kit/src/llm_kit/registry/constants.py -- the default endpoint's base URL and key env var, plus canonical and legacy credential file paths
  • packages/katsoft-llm-kit/src/llm_kit/registry/user_paths.py -- the harness-neutral user file directory under XDG; the one place the neutral path is spelled

Effort and pacing

  • packages/katsoft-llm-kit/src/llm_kit/registry/effort.py -- the effort style vocabulary (top-level, ninfer, chat_template_kwargs, reasoning-object) and the wire placement logic
  • packages/katsoft-llm-kit/src/llm_kit/registry/conserve.py -- conserve-usage pacing: the Budget verdict (available, under-quota, out-of-quota, no-data) and the ConserveSpec parser

Supporting formats

  • packages/katsoft-llm-kit/src/llm_kit/registry/adapter_names.py -- the four adapter family names and the openrouter-to-openai-compat rename mapping
  • packages/katsoft-llm-kit/src/llm_kit/registry/env_file.py -- the minimal .env KEY=VALUE reader and writer with quoting rules
  • packages/katsoft-llm-kit/src/llm_kit/registry/reply_cache.py -- the reply cache request-key and entry format reader, shared with the TypeScript package
  • packages/katsoft-llm-kit/src/llm_kit/registry/declaration_syntax.py -- the probe that returns the bootstrap model-declaration validator
