The test suite for katsoft-libs: frozen contract goldens, the llm-kit CLI and adapter behavior, the repoint from legacy plugins into the unified llm-kit package, and packaging.

The test suite for two Python distributions: katsoft-contracts and katsoft-llm-kit. It splits by distribution, then by check type. The contract side pins exact behavior with frozen goldens captured once from a reference commit and never regenerated; the llm-kit side exercises the live source tree through a shared harness that isolates HOME, scrubs ambient state, and runs the real CLI in-process. A repoint layer records the migration from three legacy plugins into the unified package, and packaging tests build and inspect the release wheel. The invariant that shapes everything: the contract goldens are literals, not computed values, so a changed error message is a deliberate act.

Where to start

Open tests/llm-kit/test_cli_harness.py for the shared environment every llm-kit test builds on; open tests/contracts/test_goldens_frozen.py when you need to verify the canonical package against its frozen behavior.

Routes

  • Add a contract case
    1. tests/contracts/contract_cases.py -- add the new input as a literal
    2. tests/contracts/contract_goldens.py -- capture its golden from the reference modules and add it in the same commit
  • Verify a release wheel
    1. tests/contracts/contract_support.py -- build the wheel the way the release machinery does
    2. tests/contracts/test_wheel_contents.py -- check every member and its metadata
  • Update a CLI golden
    1. Run tests/llm-kit/test_cli_goldens.py with UPDATE_GOLDENS=1
    2. Review the diff in tests/llm-kit/goldens/cli

Frozen contract checks

  • tests/contracts/contract_cases.py -- the fixed case list; inputs are literals so the list cannot drift with the code
  • tests/contracts/contract_goldens.py -- frozen literal results; never regenerated from the canonical package
  • tests/contracts/contract_support.py -- module loading, golden comparison, and the wheel build
  • tests/contracts/test_goldens_frozen.py -- runs the canonical package through every case and checks against the goldens
  • tests/contracts/test_package_metadata.py -- static facts: name, version, stdlib-only imports, no committed release marker
  • tests/contracts/test_wheel_contents.py -- builds the wheel and checks every member and its metadata

LLM-kit behavior

  • tests/llm-kit/test_cli_harness.py -- the shared harness: fake HOME, scrubbed env, two sides for differential parity
  • tests/llm-kit/test_cli_groups.py -- CLI routing, verb map, composition root, pinned messages
  • tests/llm-kit/test_cli_goldens.py -- golden fixtures for CLI verbs; UPDATE_GOLDENS=1 to rewrite
  • tests/llm-kit/dist_support.py -- wheel building and the isolated subprocess runner
  • 10 more tests cover consent store, account status JSON, cost-class allow filter, call modes, and claude/codex adapter behavior

Repoint and parity

  • tests/llm-kit/repoint-map.json -- the module-level migration map from legacy plugins to llm-kit
  • tests/llm-kit/porting-ledger.json -- post-map edits, each ported or rejected with evidence
  • tests/llm-kit/final_wording.py -- named deliberate wording differences between legacy and final text

Test data and fixtures

  • tests/llm-kit/fixtures -- codex JSON streams, cross-state, job and pipeline schema fixtures
  • tests/llm-kit/goldens/cli -- golden JSON files the CLI tests compare against
  • tests/llm-kit/graph -- graph module tests and their fixtures (beta, beta_ops, viewer project tree)

Packaging and scripts

  • tests/packaging -- packaging tests and probes
  • tests/repo-scripts -- repo script tests

Shared setup

  • tests/conftest.py -- pycache isolation for the whole suite
  • tests/llm-kit/conftest.py -- llm-kit path setup and ambient-state scrub
  • tests/contracts/conftest.py -- contracts fixtures; imports from the source tree, never an installed copy
