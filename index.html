Packaging, release, and reference documentation for the katsoft libraries: the contracts, llm-kit-config, and llm-kit-send packages with their PyPI and npm release pipeline and cross-language format tests.

This repository holds the katsoft libraries: standalone Python and npm packages for LLM access, durable jobs, batch pipelines, and shared file-format contracts. The core llm_kit package (completion protocol, four provider backends, dispatch, generation graphs, CLI) carries its own page one level down. The remaining packages are lighter in scope: shared type definitions, a TypeScript config reader, and a TypeScript call sender. The rest of this tree holds the PyPI and npm release pipeline, cross-language format tests that pin every shared file format, and the reference documentation that defines each format's reading and writing rules.

Where to start

Open README.md for the install command and one-line scope. Before changing a shared file format or release code, read the matching reference document; docs/reference/llm-kit-formats.md resolves any disagreement between a schema and a shared test case.

Routes

  • Release a Python package
    1. scripts/release.py --execute (plans the release set, pushes the tag)
    2. .github/workflows/release-packages.yml builds the wheel and uploads to PyPI
    3. the verified entry lands in packages/released.json
  • Release an npm package
    1. push tag @katsoft/llm-kit-config@<version>
    2. .github/workflows/release-npm.yml builds, tests, packs, and publishes
    3. scripts/npm_registry.py waits for the registry listing and compares integrity
  • Run the test suite
    1. uv run --extra dev pytest (all Python packages, worksteal)
    2. npm ci && npm test && npm run check-pack (each npm package, locked tree)

Packages and release pipeline

Three packages live here besides llm_kit: packages/katsoft-contracts (shared type definitions, Python), packages/llm-kit-config (TypeScript config reader, npm), and packages/llm-kit-send (TypeScript call sender, npm). Each carries its own examples, scripts, and test directory.

The release pipeline: scripts/release.py drives PyPI releases through scripts/_packages.py (preflight policy, observations, state transitions); scripts/npm_registry.py handles npm publish and the integrity comparison. CI runs on push to dev and on release tags via the three workflow files under .github/workflows.

Cross-language format tests

Nine format directories under tests/formats hold the shared cases that every language reader must pass (call-record, compare-case, consent, fallback-chain, project-models, prompt-file, reply-entry, reply-key, run-record). tests/contracts tests the shared type definitions. tests/llm-kit is the Python test suite with fixtures, goldens, graph fixtures, and a gated live suite. tests/packaging probes the build; tests/repo-scripts tests the release scripts.

Repository configuration

The root pyproject.toml declares dev dependencies and pytest config; uv.lock pins the dependency tree. packages/registry.toml registers the PyPI distributions and their build inputs; packages/released.json is the verified release ledger. .gitattributes enforces LF line endings on every platform (a CRLF checkout breaks every shell script). .python-version pins 3.12.
