Standalone Python distributions for LLM access and shared contracts: package manifests, the shared release build system, PyPI release tooling, CI workflows, and architecture reference documentation

This repository builds and ships two Python distributions: katsoft-llm-kit and katsoft-contracts. Each versions independently and releases to PyPI through a shared deterministic build system that guarantees a tag always rebuilds by the builder it was released with. The release tooling, CI workflows, and architecture reference documentation sit here; the llm-kit library source lives one level down. The build is the organizing principle: the registry, the ledger, the workflow, and the hatchling hooks all exist to make that guarantee hold.

Where to start

Start with pyproject.toml for the dev environment and test configuration, then docs/reference/package-release.md before changing release code or bumping a version.

Routes

  • Release a package
    1. Bump the version in the package's pyproject.toml
    2. uv run --extra dev pytest
    3. Plan: uv run --extra dev python scripts/release.py
    4. Execute after approval: uv run --extra dev python scripts/release.py --execute
  • CI on every push
    1. Push to dev
    2. .github/workflows/tests.yml runs pytest on Ubuntu and Windows
  • Build a wheel locally
    1. uv run --extra dev python packages/_build/release_build.py build --repo . --commit HEAD --dist katsoft-llm-kit --out tmp/wheels

Package manifests and registry

  • packages/registry.toml - the release registry: names each distribution, its import name, marker path, and surface file
  • packages/released.json - the release ledger: verified wheels with commit, tag, SHA-256, and verification timestamp
  • packages/katsoft-contracts/pyproject.toml - the contracts package manifest, version 1.0.1, no runtime dependencies
  • packages/katsoft-llm-kit/pyproject.toml - the llm-kit package manifest, version 1.10.1, extras for sdk, jobs, config, frontdoor, pipeline, and graph
  • packages/katsoft-llm-kit/public-surface.json - every exported name with its lifecycle status; open when checking whether a public API changed
  • packages/katsoft-contracts/src/katsoft_contracts - the contracts source: execution-event envelope, interrupt contract, and model-declaration parser

Deterministic build system

  • packages/_build/release_build.py - the single build implementation: git-archive inputs, pinned constraints, SOURCE_DATE_EPOCH, and the wheel-content check
  • packages/_build/hatch_build.py - the hatchling hooks that write the release marker and Source URL into each wheel; refuses to build without release identity
  • packages/_build/constraints.txt - pinned build dependencies; a change here invalidates every distribution's build inputs

Release command and CI

  • scripts/release.py - the release entry point: plan mode prints the release set; --execute pushes tags and records verified uploads
  • scripts/_packages.py - the release machinery: preflight policy, observations, transitions, and git operations for the dev advance and tag push
  • .github/workflows/tests.yml - CI: pytest on Ubuntu and Windows on every push and pull request to dev
  • .github/workflows/release-packages.yml - the release workflow: checks out the tag, builds with the release builder, and uploads via PyPI trusted publishing
